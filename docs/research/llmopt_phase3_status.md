# LLMOPT priority core

The implementation adds a bounded internal football-planning core. It certifies the
required plan's decisions, recomputes its integer objective, applies a total concession
floor, maximizes up to three count layers, and then points. Actual solver work uses the
existing allocation. Uncompleted layers retain the previous completed witness.

`python -m pytest tests/unit/test_priority_preferences.py -q` runs 22 cases. The independent
oracle enumerates all 16 final transfer packages and both legal lineups in each tiny
football case, rather than calling the production optimizer for its expected answer.
Other cases cover exact boundaries, conflicting soft/hard rules, all six writing-order
permutations, a forged numeric reference claim, three weeks and interrupted layers.

## Incomplete integration

This is not the Phase 3 acceptance result. Public advice admission, immutable job specs,
worker reference retrieval, legacy price bundling, provider interpretation fields, editor,
result cards and conversation coverage are not connected to this core. The proposed
program schema is internal only; the API continues rejecting these absent wire fields.
No page begins sending an unsupported contract.

The unchanged Phase 1 record and Phase 2 admission replay still describe the page's
four-job preference path. There is no measured reduction to two jobs and no claim of a
new 20-member quality or runtime measurement. Replacing it requires a single preference
job that retrieves the exact server-computed main plan and preserves legacy individual
ceiling behavior. The next phase may develop independent device functionality, but may
not claim migration of this incomplete server integration.
